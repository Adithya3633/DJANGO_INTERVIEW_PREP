# MODULE 4 – React Hooks
## 43. What are Hooks in React?
Hooks are special React functions that let functional components use React features such as state, context, refs and Effects. Introduced in React 16.8.
- useState
- useEffect
- useRef
- useContext
- useReducer
- useMemo
- useCallback
- useId
## 44. What are the Rules of Hooks?
- Call Hooks only at the top level of React function components or custom Hooks.
- Do not call Hooks inside loops, conditions or nested functions.
```jsx
// Incorrect
if (true) {
  const [count, setCount] = useState(0);
}

// Correct
const [count, setCount] = useState(0);
```
## 45. What is useState?
A Hook that adds state to a functional component.
```jsx
const [state, setState] = useState(initialValue);

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <>
      <h2>{count}</h2>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <button onClick={() => setCount(count - 1)}>Decrement</button>
    </>
  );
}
```
## 46. What is the difference between useState and normal variables?
| Normal variable | useState |
| Stores regular JavaScript data | Stores component state |
| Changes do not trigger re-render | Setter schedules re-render |
| Value may be recalculated on render | State is preserved across renders |
| Not suitable for UI state | Suitable for dynamic UI |
## 47. Why should we not update state directly?
Directly modifying state does not notify React that an update is needed. Use the setter function.
```jsx
// Incorrect
count = count + 1;

// Correct
setCount(count + 1);
```
## 48. What is functional state updating?
Passing a function to a state setter. Useful when the new state depends on the previous state. React may batch updates, and the functional updater receives the latest queued state.
```jsx
setCount(prevCount => prevCount + 1);
```
## 49. What happens when we call setState multiple times?
```jsx
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);
```
These all use the same value of count from the current render, so the result is generally an increase of 1. Correct approach (increases by 3):
```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```
## 50. What is useEffect?
A Hook used to synchronize a component with external systems.
- Fetching API data
- Setting up event listeners
- Timers and intervals
- Subscriptions
- Synchronizing with browser APIs
```jsx
useEffect(() => {
  // Effect logic
  return () => {
    // Cleanup logic
  };
}, [dependencies]);
```
## 51. What are the three types of useEffect dependency patterns?
1. Without dependency array: runs after every commit in which the component is rendered.
2. Empty array: runs after the initial mount. In development StrictMode, React may run an additional setup/cleanup cycle.
3. With dependencies: runs after the initial mount and whenever a dependency changes.
```jsx
useEffect(() => { console.log("After every commit"); });
useEffect(() => { console.log("Mount effect"); }, []);
useEffect(() => { console.log("Count changed"); }, [count]);
```
## 52. What is the difference between useState and useEffect?
| useState | useEffect |
| Manages component state | Synchronizes with external systems |
| Stores changing values | Runs side-effect logic |
| Setter schedules rendering | Runs after a commit |
| Used for counters, forms, etc. | Used for API calls, timers, listeners |
## 53. What is cleanup in useEffect?
A function returned from an Effect, used to remove subscriptions, event listeners, timers and other external resources.
```jsx
useEffect(() => {
  const id = setInterval(() => {
    setSeconds(prev => prev + 1);
  }, 1000);

  return () => {
    clearInterval(id);
  };
}, []);
```
Interview point: cleanup runs before an Effect re-executes with changed dependencies and when the component unmounts.
## 54. What is the difference between useEffect and useLayoutEffect?
| useEffect | useLayoutEffect |
| Runs after DOM commit | Runs after DOM mutations but before browser repaint |
| Generally does not block painting | Can block painting |
| Suitable for most side effects | Useful for layout measurements and synchronous visual adjustments |
Prefer useEffect unless you specifically need to measure or adjust layout before the browser paints.
## 55. Can we use async directly inside useEffect?
Do not make the Effect callback itself async: an async function returns a Promise, while React expects an optional cleanup function. Define an async function inside and call it.
```jsx
useEffect(() => {
  async function getUsers() {
    const response = await fetch("https://jsonplaceholder.typicode.com/users");
    const data = await response.json();
    setUsers(data);
  }
  getUsers();
}, []);
```
## 56. What is useRef?
Stores a mutable value between renders without triggering a re-render when it changes.
- Accessing DOM elements
- Storing timer IDs
- Keeping mutable values not required for rendering
```jsx
const inputRef = useRef(null);

function focusInput() {
  inputRef.current.focus();
}

<input ref={inputRef} />
<button onClick={focusInput}>Focus Input</button>
```
## 57. Difference between useState and useRef?
| useState | useRef |
| Used for UI state | Used for mutable references |
| Updating triggers re-render | Updating does not trigger re-render |
| Access through state variable | Access through .current |
| Used for forms, counters | Used for DOM access, timer IDs |
## 58. What is useContext?
Accesses values from a React Context without passing props through every intermediate component.
```jsx
const UserContext = createContext();

function Profile() {
  const user = useContext(UserContext);
  return <h2>{user}</h2>;
}

function App() {
  return (
    <UserContext.Provider value="Adithya">
      <Profile />
    </UserContext.Provider>
  );
}
```
## 59. What is Context API?
A React feature that lets components share data without manually passing props through every level.
- Theme
- Logged-in user information
- Language preference
- Shared application settings
## 60. What is useReducer?
A Hook that manages state through a reducer function. Useful when state logic is complex or involves multiple related updates.
```jsx
function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };
    case "decrement":
      return { count: state.count - 1 };
    default:
      return state;
  }
}

const [state, dispatch] = useReducer(reducer, { count: 0 });

<button onClick={() => dispatch({ type: "increment" })}>+</button>
```
## 61. Difference between useState and useReducer?
| useState | useReducer |
| Simple state management | Complex state management |
| Direct setter | Dispatches actions |
| Less code | More structured logic |
| Good for counters and inputs | Good for complex related updates |
## 62. What is useMemo?
Caches the result of a calculation between renders until its dependencies change, avoiding expensive recalculation.
```jsx
const total = useMemo(() => {
  return products.reduce((sum, product) => sum + product.price, 0);
}, [products]);
```
Interview point: don't use it everywhere. Memoization has a cost, so use it when it gives a meaningful benefit.
## 63. What is useCallback?
Caches a function definition between renders until its dependencies change. Useful when passing callbacks to memoized child components or when a stable function reference matters.
```jsx
const handleClick = useCallback(() => {
  console.log("Button clicked");
}, []);
```
## 64. Difference between useMemo and useCallback?
| useMemo | useCallback |
| Caches a calculated value | Caches a function |
| Returns the memoized result | Returns the memoized function |
| Useful for expensive calculations | Useful for stable callback references |
## 65. What is a custom Hook?
A reusable JavaScript function that uses React Hooks and whose name starts with use.
```jsx
function useCounter() {
  const [count, setCount] = useState(0);

  function increment() {
    setCount(prev => prev + 1);
  }

  return { count, increment };
}

const { count, increment } = useCounter();
```
## 66. What is the difference between useEffect and useMemo?
useEffect performs synchronization with external systems after a commit. useMemo caches the result of a calculation during rendering.
- useEffect: fetch data from an API
- useMemo: calculate the total price of 10,000 products
## 67. What is the component lifecycle?
The stages a component goes through:
- Mounting – component is added to the UI
- Updating – component re-renders due to changes
- Unmounting – component is removed from the UI
Function components commonly use Effects for synchronization and cleanup.
## 68. What are lifecycle methods in class components?
| Method | Purpose |
| componentDidMount() | Runs after mounting |
| componentDidUpdate() | Runs after updates |
| componentWillUnmount() | Runs before unmounting |
These are relevant when maintaining older React applications.
